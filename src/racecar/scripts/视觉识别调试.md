# 红绿灯和人行道识别调试说明

本文用于调试 `traffic_light_detector.py` 的红绿灯识别和人行道识别。`go.py` 只负责接收 `/road_perception` 的结果并停车/恢复，识别不准时优先调 `traffic_light_detector.py`，不要先改导航或底盘代码。

## 程序关系

```text
摄像头
  -> traffic_light_detector.py
  -> 发布 /road_perception
  -> go.py 接收 /road_perception
  -> 红灯/人行道时拦截 /cmd_vel，向 /car_cmd_vel 发停车速度
```

`/road_perception` 的消息格式是 JSON 字符串：

```json
{"traffic_light":"RED", "crosswalk":false}
```

字段含义：

- `traffic_light`：`RED`、`GREEN`、`UNKNOWN`
- `crosswalk`：`true` 表示检测到人行道，`false` 表示未检测到

## 先确认程序是否正常运行

进入脚本目录：

```bash
cd ~/racecar/src/racecar/scripts
```

启动识别程序：

```bash
python3 traffic_light_detector.py
```

另开一个终端查看发布结果：

```bash
ros2 topic echo /road_perception
```

正常情况下，应该能看到类似输出：

```text
data: '{"traffic_light": "GREEN", "crosswalk": false}'
```

如果没有输出，先检查：

```bash
ros2 topic list | grep road_perception
ls /dev/video*
```

如果程序提示 `camera open failed: /dev/video20`，说明摄像头编号不对或被其他程序占用。修改 `traffic_light_detector.py` 顶部的：

```python
CAMERA_INDEX = 20
```

## 看预览窗口判断问题

`traffic_light_detector.py` 默认会显示 OpenCV 预览窗口：

```python
SHOW_CAMERA_IMAGE = True
```

窗口里重点看这些文字：

- `STATE=RED/GREEN/UNKNOWN`：稳定后的红绿灯结果
- `raw=RED/GREEN/UNKNOWN`：当前帧原始识别结果
- `crosswalk=True/False`：稳定后的人行道结果
- `raw=True/False`：当前帧原始人行道结果
- `white=...`：人行道区域白色面积比例
- `valid=...`：满足人行道形状条件的有效面积比例
- `papers=...`：识别到的白色纸块数量
- `crosswalk detector=ACTIVE/LOCKED`：人行道检测是否已经触发锁定

如果看不到窗口，通常是 SSH 没有开 X11 转发。可以先通过 `/road_perception` 话题调试，或者在支持 X11 的终端里运行。

## 红绿灯识别调试

红绿灯相关参数在 `traffic_light_detector.py` 顶部：

```python
ROI_TOP_RATIO = 0.30
ROI_BOTTOM_RATIO = 0.78
ROI_LEFT_RATIO = 0.05
ROI_RIGHT_RATIO = 0.95

COLOR_HSV_RANGES = {
    "red": [
        ((0, 45, 70), (15, 255, 255)),
        ((163, 45, 70), (179, 255, 255)),
    ],
    "green": [
        ((32, 25, 70), (105, 255, 255)),
    ],
}

MIN_COMPONENT_AREA = 40
SCORE_VALUE_FLOOR = 150
MIN_ACTIVE_SCORE = 45.0
CONFIRM_FRAMES = 2
```

### 红绿灯完全识别不到

先看红绿灯是否在识别区域内。识别区域由这几个比例决定：

```python
ROI_TOP_RATIO
ROI_BOTTOM_RATIO
ROI_LEFT_RATIO
ROI_RIGHT_RATIO
```

调整原则：

- 灯在画面更上方：减小 `ROI_TOP_RATIO`
- 灯在画面更下方：增大 `ROI_BOTTOM_RATIO`
- 灯在画面边缘：扩大 `ROI_LEFT_RATIO` 和 `ROI_RIGHT_RATIO` 的范围

如果区域没问题，再降低识别门槛：

```python
MIN_ACTIVE_SCORE = 30.0
MIN_COMPONENT_AREA = 20
```

降低后更容易识别，但也更容易误识别。

### 红灯被识别成 UNKNOWN

可以放宽红色 HSV 范围。红色有两段，因为 HSV 的红色跨越 0 度：

```python
"red": [
    ((0, 45, 70), (15, 255, 255)),
    ((163, 45, 70), (179, 255, 255)),
]
```

常见调整：

- 红灯偏暗：降低第三个值的下限，例如 `70` 改成 `50`
- 红色不够饱和：降低第二个值的下限，例如 `45` 改成 `30`
- 红灯色相偏移：适当扩大 H 范围，例如 `15` 改成 `20`，`163` 改成 `158`

### 绿灯被识别成 UNKNOWN

调整绿色 HSV：

```python
"green": [
    ((32, 25, 70), (105, 255, 255)),
]
```

常见调整：

- 绿灯偏暗：降低 V 下限，例如 `70` 改成 `50`
- 绿灯颜色偏淡：降低 S 下限，例如 `25` 改成 `15`
- 绿灯颜色偏黄或偏蓝：扩大 H 范围，例如 `32` 改成 `25`，`105` 改成 `115`

### 红绿灯误识别

如果把环境反光、彩色物体误识别成红灯或绿灯，优先收紧识别条件：

```python
MIN_ACTIVE_SCORE = 60.0
MIN_COMPONENT_AREA = 80
CONFIRM_FRAMES = 3
```

调整效果：

- `MIN_ACTIVE_SCORE` 越大，越不容易触发红绿灯
- `MIN_COMPONENT_AREA` 越大，小反光点越容易被过滤掉
- `CONFIRM_FRAMES` 越大，结果越稳定，但反应更慢

如果误识别只出现在画面边缘或地面反光，优先缩小 ROI，不要盲目改 HSV。

## 人行道识别调试

人行道相关参数：

```python
CROSSWALK_ROI_TOP_RATIO = 0.55
CROSSWALK_ROI_BOTTOM_RATIO = 1.00
CROSSWALK_ROI_LEFT_RATIO = 0.02
CROSSWALK_ROI_RIGHT_RATIO = 0.98

CROSSWALK_WHITE_MIN_VALUE = 190
CROSSWALK_WHITE_MAX_SATURATION = 70
CROSSWALK_MIN_WHITE_AREA_RATIO = 0.08
CROSSWALK_MIN_VALID_AREA_RATIO = 0.055
CROSSWALK_MIN_BLOB_AREA_RATIO = 0.012
CROSSWALK_MIN_BLOB_FILL_RATIO = 0.62
CROSSWALK_MIN_HEIGHT_WIDTH_RATIO = 0.70
CROSSWALK_MAX_HEIGHT_WIDTH_RATIO = 4.50
CROSSWALK_MIN_BLOBS = 2
CROSSWALK_MIN_CENTER_SPAN_RATIO = 0.16
CROSSWALK_CONFIRM_FRAMES = 1
```

### 人行道完全识别不到

先看 `white`、`valid`、`papers`：

- `white` 很低：白色阈值太严格，或者人行道不在 ROI 内
- `valid` 很低：白色区域有了，但形状条件没通过
- `papers=0`：没有找到有效白色纸块

常见调整：

```python
CROSSWALK_WHITE_MIN_VALUE = 170
CROSSWALK_WHITE_MAX_SATURATION = 90
CROSSWALK_MIN_WHITE_AREA_RATIO = 0.05
CROSSWALK_MIN_VALID_AREA_RATIO = 0.035
CROSSWALK_MIN_BLOB_AREA_RATIO = 0.008
```

调整含义：

- 降低 `CROSSWALK_WHITE_MIN_VALUE`：较暗的白纸也能识别
- 增大 `CROSSWALK_WHITE_MAX_SATURATION`：带一点颜色偏差的白纸也能识别
- 降低面积比例：距离远、面积小时更容易触发

### 人行道误触发

如果地面反光、白墙、白板、白色装饰被识别成人行道，收紧条件：

```python
CROSSWALK_WHITE_MIN_VALUE = 210
CROSSWALK_WHITE_MAX_SATURATION = 50
CROSSWALK_MIN_WHITE_AREA_RATIO = 0.10
CROSSWALK_MIN_VALID_AREA_RATIO = 0.08
CROSSWALK_MIN_BLOB_AREA_RATIO = 0.018
CROSSWALK_MIN_BLOBS = 3
CROSSWALK_CONFIRM_FRAMES = 2
```

调整含义：

- 提高 `CROSSWALK_WHITE_MIN_VALUE`：只接受更亮的白色
- 降低 `CROSSWALK_WHITE_MAX_SATURATION`：排除带颜色的区域
- 提高面积比例：小白块不触发
- 提高 `CROSSWALK_MIN_BLOBS`：至少检测到更多纸条才触发
- 提高 `CROSSWALK_CONFIRM_FRAMES`：连续多帧识别才确认

### 人行道只触发一次

当前程序设计为人行道“一次触发后锁定”：

```text
crosswalk detector=LOCKED
```

这是为了避免小车经过人行道后反复停车。重新测试人行道时，需要重启 `traffic_light_detector.py`。

## 调试建议顺序

1. 先确认摄像头能打开，画面正常。
2. 确认 `/road_perception` 有输出。
3. 先调 ROI，让红绿灯和人行道落在识别区域内。
4. 再调 HSV 或白色阈值。
5. 最后调面积、帧数、形状条件。
6. 每次只改 1 到 2 个参数，重启程序观察效果。

修改后先做语法检查：

```bash
python3 -m py_compile traffic_light_detector.py
python3 -m py_compile go.py
```

再启动：

```bash
python3 traffic_light_detector.py
```

确认话题输出正确后，再启动导航：

```bash
python3 go.py
```

## go.py 停车行为确认

当前 `go.py` 的停车逻辑是：

```text
正常：转发 /cmd_vel 到 /car_cmd_vel
红灯：向 /car_cmd_vel 持续发布 linear.x=0.0, angular.z=0.0
绿灯：恢复转发 /cmd_vel
人行道：停车 CROSSWALK_STOP_DURATION 秒后恢复
```

如果识别话题已经是 `RED`，但车不停，检查：

```bash
ros2 topic echo /road_perception
ros2 topic echo /car_cmd_vel
ros2 topic list | grep cmd_vel
```

预期：

- 红灯时 `/road_perception` 里应出现 `"traffic_light": "RED"`
- 红灯时 `/car_cmd_vel` 应持续出现 `linear.x = 0.0`
- 如果 `/car_cmd_vel` 仍有其他非零速度，说明可能还有其他节点也在发布 `/car_cmd_vel`

如果红灯后不能恢复，检查 `/road_perception` 是否从 `RED` 变成了 `GREEN`。当前 `go.py` 只有收到 `GREEN` 才会解除红灯停车。
